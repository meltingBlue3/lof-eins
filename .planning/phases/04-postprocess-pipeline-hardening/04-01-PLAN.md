<objective>
Wire the validation gate end-to-end: `validate()` returns its findings instead of only printing them, `postprocess()` refuses to write `limit_events` when there are any findings, and `scripts/parse_announcements.py` prints those findings and exits non-zero. This is the phase's tracer — one path through every layer the phase touches (validation -> orchestration -> CLI -> exit code), plus the temp-database test harness every later plan in this phase reuses.

Purpose: STAB-02. `postprocess.py` shipped a silent 7x-PnL-inflation correctness bug once; the write path must be able to refuse bad data rather than print a warning nobody reads.
Output: `ValidationBlockedError`, a `validate()` that returns `List[str]`, a gated `postprocess()`, a non-zero CLI exit path, and `tests/test_postprocess.py` with its shared temp-DB base class.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM-extracted announcement data -> `subscription_restrictions` | Records originate from Kimi K2.5 parsing of third-party PDFs; content is untrusted and can be malformed, contradictory, or hallucinated. |
| `subscription_restrictions` -> `limit_events` | The transform this phase hardens. Everything downstream (backtest PnL) trusts `limit_events` implicitly. |
| `postprocess()` -> operator | The only signal the operator receives about data quality is what the CLI prints and the exit code it returns. |

Scope note: this is a local, single-user data pipeline with no network listener, no authentication surface, and no multi-tenant data. Web-application threat categories (CSRF, XSS, session fixation, authorization bypass) do not apply and are deliberately omitted rather than fabricated.
