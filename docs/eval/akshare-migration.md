# 行情数据换成 AKShare

- 时间：2026-11-19
- 改了什么：日线和 LOF 名单不再来自聚宽（JoinQuant），改由 AKShare 提供，不再需要账号。默认用新浪日线（`ak.fund_etf_hist_sina`），可选东方财富（`ak.fund_lof_hist_em`，`--source eastmoney`）。单位净值本来就来自 AKShare（`ak.fund_open_fund_info_em`），没变。
- 没改的：公告仍直连东方财富。AKShare 只有分红、定期报告、人事三类公告，没有限购公告所在的分类。交易条款仍用自己的天天基金费率页解析器（`src/data/fund_terms.py`）。
- 数据：`data/real_all_lof/market`、`nav` 已换成新数据（410 只基金重下，区间 2021-01-01 ~ 2024-12-31）。原聚宽文件在 `data/real_all_lof/_joinquant_backup/`。

## 2. 回测分解

区间 2022-01-04 ~ 2024-12-31，阶段 F 的设置（各基金费率、各基金可卖日、决策时可见的净值），每步只改一项：

| 步骤 | 保守 总收益 | 保守 买入/卖出 | 乐观 总收益 | 乐观 买入/卖出 |
|---|---:|---:|---:|---:|
| A. 聚宽数据，原代码（与阶段 F 报告逐字节相同） | −46.03% | 1134 / 1129 | +64.57% | 2038 / 2029 |
| B. 聚宽数据，修正 `nav_published` 后 | −46.09% | 1133 / 1128 | +64.57% | 2038 / 2029 |
| C. 新浪数据，按聚宽的方式补齐无成交日 | −46.09% | 1133 / 1128 | +64.57% | 2038 / 2029 |
| D. 新浪数据原样（无成交日没有记录） | −45.37% | 1148 / 1132 | +28.30% | 1914 / 1880 |

- **A → B**：`nav_published` 原来按行情行数往前移 `nav_lag` 行。行情缺行时会取到更早的净值。现在改为在净值自己的日期上取 T 之前的第 `nav_lag` 个净值（`src/data/loader.py` 的 `published_nav`）。在聚宽数据上只影响一笔往返。
- **B → C**：成交记录和每日净值逐字节相同。新浪数据本身和聚宽等价，28 个成交量为 0 的日子没有影响到任何交易。
- **C → D**：差别全部来自无成交日。聚宽数据在这些日子有记录，引擎卖出时不看成交量，所以会按前收盘价卖出任意数量。B 的成交记录里，保守边界 1128 笔卖出中有 66 笔（5.9%）、乐观边界 2029 笔中有 193 笔（9.5%）发生在无成交日；买入则没有，因为流动性上限为 0。新数据里这些日子没有记录，策略只能等下一个有成交的日子卖出，按当天的价格成交。

## 4. 东方财富接口的两个问题

下载器保留了东方财富作为可选来源，但它在这台机器上有两个问题，这也是默认改用新浪的原因：

- 东方财富 push2 行情服务器会直接断开带默认 `python-requests` User-Agent 的请求（直连和走代理都一样），AKShare 1.20.65 的 `fund_lof_hist_em` 和 LOF 板块接口发的正是这个 User-Agent。下载器在请求期间换成浏览器 User-Agent。
- 短时间约 6 次请求就会被封 IP；被封期间继续请求会延长封禁，这次超过一小时仍未恢复。另外，`fund_lof_hist_em` 每查一只基金都会重新拉一遍 4 页的 LOF 板块，下载器改为整次运行只查一次（不在板块上的代码按前缀判断交易所：5 开头为上海，其余为深圳）。

新浪 410 次请求、间隔约 1.5 秒，没有遇到限制，约 13 分钟下完。

## 5. 复现

```bash
python scripts/download_lof.py --tickers-from data/real_all_lof/_joinquant_backup --output data/real_all_lof/_staging
```

逐只对比、分解和逐步叠加的脚本是一次性的，没有放进仓库；上面的数字可以用 `run_backtest.py --bounds -s 2022-01-04` 和 `--sensitivity -s 2022-01-04` 分别在新数据和备份数据（把 `data_dir` 指向一份含 `market`、`nav`、`config` 的目录）上重跑得到。
